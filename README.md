# ActionRecorder alpha 0.0.1

Явный консольный recorder для Windows 10/11, предназначенный для создания
визуальных тест-кейсов другого приложения. Запись фильтруется по имени
исполняемого файла целевого процесса и не сохраняет набранный текст.

## Требования

- Windows 10 или новее, x64
- Visual Studio 2022 (Desktop development with C++) или MSVC
- CMake 3.16+
- SDK Windows с `UIAutomation.h`

## Сборка

```powershell
cmake -S . -B build -A x64
cmake --build build --config Release
```

Исполняемый файл будет расположен в `build/Release/ActionRecorder.exe`.
Проект использует C++17 и флаг `/utf-8` для MSVC. Этот флаг одновременно
задаёт UTF-8 для исходных файлов и строк выполнения; отдельные charset-флаги
на новых версиях MSVC несовместимы с `/utf-8`.

Также сборку можно выполнить из Visual Studio: откройте корень репозитория
через «Open Folder» или сгенерируйте решение через CMake.

## Запуск

```powershell
.\build\Release\ActionRecorder.exe --target=ADHD-limiter.exe
```

При запуске программа выводит `ActionRecorder alpha 0.0.1` и открывает
стандартный диалог сохранения Проводника. Пользователь выбирает папку и
базовое имя файла. Консольный ввод пути или имени не используется.

Файл создаётся как `[Имя][ГГГГММДД_ЧЧММСС].txt`, например:
`log20250410_153022.txt`.

Для остановки нажмите `Ctrl+Shift+Q`. Можно закрыть консольное окно,
однако корректное завершение через сочетание клавиш освобождает хуки.

Если аргумент `--target=...` не указан, хуки не устанавливаются. Это
предотвращает случайную системную запись вне явного режима тестирования.

## Модель безопасности

- Перед запуском видно имя целевого процесса и активный консольный индикатор.
- События клавиатуры и мыши записываются только для окон активного процесса.
- Текст клавиатуры, буфер обмена и содержимое экранных полей не сохраняются.
- Нажатые клавиши представлены только Win32 `VK_CODE`.
- Для остановки используется глобальное сочетание `Ctrl+Shift+Q`.
- Отменённый диалог сохранения завершает приложение без установки хуков.
- Исходный код, пример лога, сборочные параметры и список известных
  ограничений опубликованы вместе с бинарником.

## Формат лога

Файл начинается с UTF-8 BOM (`EF BB BF`) и статичного заголовка. Каждая строка
имеет формат:

```text
[TIMESTAMP] | [OBJECT_IDENTIFIER] | [ACTION] | [DURATION_MS]
```

- `TIMESTAMP`: локальное время `ЧЧ:ММ:СС.ммм`.
- `OBJECT_IDENTIFIER`: `UIA:ControlType(Name="...", AutomationId="...")`
  при успешном UI Automation или `POS:Mouse(X=..., Y=...)` при fallback.
- `ACTION`: `KeyPress(VK_CODE)`, `KeyRelease(VK_CODE)`,
  `MouseDown(LEFT|RIGHT)` или `MouseClick(LEFT|RIGHT)`.
- `DURATION_MS`: длительность нажатия или интервал до предыдущего действия.

Приложение не записывает символы или содержимое буфера обмена. Для клавиш
сохраняется только Win32 `VK_CODE` и состояние press/release.

## Кодировка

Все исходные файлы должны сохраняться в UTF-8. CMake передаёт MSVC флаги UTF-8,
а консоль переключается на кодовую страницу UTF-8. Лог-файлы всегда открываются
в бинарном режиме, начинаются с BOM и содержат текст в UTF-8. Русские символы
в свойствах UI Automation `Name` и `AutomationId` должны корректно отображаться.

## Известные ограничения alpha

- Возможны пропуски событий при высокой нагрузке или старте хука в процессе
  блокировки/смены фокуса приложения.
- Долгие нажатия и последовательные действия определяются локально по таймерам.
- Низкоуровневый клавиатурный хук не позволяет надёжно восстанавливать произвольный
  ввод текста на уровне отдельных символов во всех приложениях.
- UI Automation может быть недоступен в приложениях с повышенными привилегиями
  или при использовании remote desktop/container; в этом случае используется
  координатный fallback.
- Версия предназначена для тестирования на разных конфигурациях Windows.

## Совместимость с ADHD-limiter

Проект совместим при запуске recorder с
`--target=ADHD-limiter.exe`. Тестируются основные элементы UI:
разметка «Работа»/«Отдых», кнопки Пуск/Пауза/Подтверждение/Сброс,
поля редактирования минут и имён. Для разных сборок имя исполняемого
файла остаётся `ADHD-limiter.exe`, как указано в установочном CMake.
Сам `ADHD-limiter` не требует изменений и не получает зависимости recorder.

Из-за legacy/static Win32-контролов AutomationId может быть пустым:
UI Automation всё равно сможет вернуть Name и ControlType для многих элементов,
а при недоступности используется координатный fallback.
